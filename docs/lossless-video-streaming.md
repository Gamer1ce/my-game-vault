# 原画分段播放

适用于体积大、码率高的 H.264/AAC 游戏录像。视频以 FFmpeg `-c copy` 重封装成 fMP4 HLS，不重新编码，不改变分辨率、帧率或音视频压缩数据。访客按约 2 秒的小段读取，支持跳转；分段边界取决于原片关键帧，并非严格两秒。

## 在媒体所在的电脑准备

电脑需要安装 FFmpeg 和 FFprobe。在项目目录执行（第二个参数为媒体根目录下的相对文件名）：

```sh
node scripts/prepare-highlight-stream.mjs "/Volumes/游戏视频" "某个游戏/录像.mp4"
```

完成后刷新网站即可。这里只处理明确指定的文件，不会自动遍历或改写整个硬盘。已有完整缓存会跳过。其他编码保留原文件播放，不自动有损转换。

缓存位于媒体根目录的隐藏目录 `.playback-cache/`，大约额外占用一份原片的空间，不占 Mac 系统盘。原视频和目录结构保持不变，缓存不会出现在精彩时刻清单。原文件删除或修改后，旧缓存接口立即失效。生成只允许通过本机脚本进行，访客不能触发转码任务，也不能通过接口读取缓存元数据或任意隐藏文件。

## 直连反向代理

媒体域名需同时转发以下两类只读路径到网站后端，其余路径仍返回 404：

```caddyfile
@media path /media/highlights/* /media/highlight-streams/*
handle @media {
    reverse_proxy game-vault:4173
}
respond 404
```

播放器沿用已经选中的媒体节点，不把分段自动转到另一家代理。节点没有分段缓存或设备不支持时，回退同节点原文件。Azure 镜像默认排除隐藏目录，不会自动上传这份额外缓存；需要分段播放的节点应单独准备，且先检查可用磁盘。

## 缓冲与设备限制

播放器检测到暂停后已有至少 1.5 秒缓存、但连续 4 秒不再增长时，会结束无效的攒缓存等待；原生播放即使仍报告 `NETWORK_LOADING` 也适用。该视频确认无法在暂停时继续缓存后，不再重复强制暂停，交回浏览器正常续播。切换新视频才重新评估。分片模式不把正在传输的大分片误判为停止；Safari ManagedMediaSource 明确发出 `endstreaming` 时才按暂停预加载处理。

设备同时提供标准 MediaSource 和 ManagedMediaSource 时优先标准 MediaSource；只有后者可用的设备仍使用 ManagedMediaSource，并跟踪其开始/停止预加载信号。私人原文件起播也采用上述检测，不再固定等待 20 秒后才放行几秒缓存。缓存达到目标时正常开始，正在增长时继续积累，不改变原画码率。

本机回归工具 `scripts/playback-native-lab.mjs` 接受媒体根目录和文件名，仅监听 `127.0.0.1:8418`，可测试限速原文件播放。它不连接 Cloudflare、不修改原片；每个响应限制约 50 Mbps，多请求并发时不是整个系统的总带宽限速器。桌面浏览器结果不能替代访客手机蜂窝网络实测。

支持 MediaSource / ManagedMediaSource 的设备使用本地托管的 hls.js，目标向前缓存约 16 秒、保留约 4 秒已播放内容，不下载整部视频到内存。内存预算是播放器配置目标，不是设备承诺；浏览器仍可能主动缩小缓存。偶发断流仍交给 HLS / 浏览器恢复；实际播放后若 30 秒内两次独立缺缓存，则暂停消耗、积累最多 16 秒真实可播放缓存再继续，减少短促的停播循环。用户可立即播放、跳转或关闭，操作优先于自动恢复；原生浏览器暂停后不再加载、达到片尾或等待过久时有有界退路，不强求无法达到的缓存量。缓存充足的解码卡顿不触发此策略。分段解析由同源托管的 Web Worker 在后台线程处理，避免挤占页面主线程；不需要开放外部脚本或 blob Worker 权限。

访客播放页只保留视频、简短的缓冲/错误提示和必要的播放/换线按钮，正常播放时隐藏重复播放按钮。线路测速、平均码率、缓存条和掉帧诊断不出现在访客界面；管理员可展开“播放诊断”查看。关闭诊断时不持续刷新它的内容。

打开视频弹窗时会自动启用下述“视频优先”，无需访客操作或额外提示面板。

在支持的 iPhone 上，为启用 ManagedMediaSource，本模式禁用 Remote Playback / AirPlay；旧设备原生 HLS 模式不禁用。具体平台要求见 [WebKit 官方说明](https://webkit.org/blog/14735/webkit-features-in-safari-17-1/)。内置 hls.js 1.7.3 来自 npm 官方注册表，使用 Apache-2.0 许可证；源码项目为 [video-dev/hls.js](https://github.com/video-dev/hls.js)，许可证保留在 `public/vendor/hls.js-LICENSE.txt`。

分段和缓存可以改善加载控制，但不会减少原画所需流量。例如 5 分钟、3.4GB 原片平均约 91Mbps；持续线路吞吐不足时仍需等待，设备解码能力不足也不能靠加大缓存解决。

首页优先验证家庭 IPv6 直连的 512 KiB 头部和 64 KiB 尾部 Range，成功后立即使用，兼容线路仅保留为后备，不等待海外代理测速或用其短样本速度覆盖可用直连。直连失败时才使用兼容线路；没有家庭直连候选的其他媒体仍沿用有限样本排序。这是连通性验证，不能代表访客的持续带宽。

关闭或更换视频立即取消未完成的选路请求；节点忽略 Range 返回整文件时立即取消正文，避免旧请求在后台占用带宽。实际播放连续 30 秒既无播放进度、无可播放缓存进展、也没有新的分片字节，且缓存不足半秒时才尝试下一条备用线路，并保留播放位置。大分片尚未解码但正在下载时不会误换线。用户主动暂停、正在跳转和缓存充足时不会自动换线；备用线路最多依次尝试一次。

## 视频优先

打开视频弹窗（包括选路、缓冲、暂停期间）自动暂停本页的非媒体 GET 读取：未完成的请求会取消并在关闭视频后重试，新的读取暂存等待，留言和状态定时刷新直接跳过，不累计轮询任务。游戏列表自动追加、尚未加载的日历等板块也延后；未完成的背景海报和缩略图暂时撤下网络地址，关闭视频后恢复原地址及懒加载设置。已加载图片不重复处理，弹窗内的视频及截图不受影响。关闭视频还会释放原媒体地址，避免旧播放器继续占用连接。

视频地址获取、线路检测、原视频和分段请求不进入暂停队列；管理操作、留言等写入不会被自动取消或重放。网站后台每小时同步仍正常运行。背景动画在选路阶段就暂停。

这是当前网页内的资源调度，并非设备或路由器的带宽保留：不能控制其他 App、其他访客、服务器上的同步上传，也不能保证移动线路的持续速度。浏览器对已经发出的图片请求会尽力取消，已传输的字节不能收回。原画码率和视频质量保持不变。
