# 私人 CPA 远程调用

CPA 通过主站的 `/cpa/v1` 提供 OpenAI 兼容接口。游戏网站不提供公开聊天框，也不在网页、JavaScript、URL 或此仓库中保存 CPA 密钥。

## 客户端设置

- API Base URL：`https://你的域名/cpa/v1`。使用完整 HTTPS 地址，不使用 HTTP，也不在地址后添加密钥参数。
- API Key：在本机 CPA 管理后台复制一枚 **CPA 客户端访问密钥**，填入你自己的客户端密钥栏。不要使用管理密钥或上游账号令牌。
- 模型：先让客户端读取模型列表，再选择实际可用的模型。
- 本机管理页仍在 `http://127.0.0.1:8317/management.html`；公网的管理页和配置接口返回 404。

访问密钥相当于密码，持有它的人可以消耗你的模型额度。只配置在可信客户端，不发送给朋友，不截图公开；怀疑泄漏时，在本机 CPA 删除该访问密钥并更换。上游密钥和 OAuth 文件始终留在 CPA 服务端，但远程客户端必须保存它自己的 CPA 访问密钥，无法保证被盗客户端中的密钥仍安全。

## 公网防护

参考 [Caddy 路由片段](../deploy/cpa/Caddyfile.snippet)。将片段放入 HTTPS 站点内，并确保 Caddy 与 CPA 共享必要的 Docker 网络。

将该网络同时写入 Caddy 的 Compose 服务配置（`networks: [default, cpa]`），并在顶层声明 `networks.cpa.external: true`、`networks.cpa.name: cliproxyapi-network`。不要只临时执行网络连接，否则重建容器后可能失联；网络名称应以你自己的 CPA 配置为准。不要把 CPA 的密钥文件或认证目录挂载到游戏网站的公开静态目录。

- 仅放行明确列出的模型列表、聊天、Responses 和消息接口；管理、认证回调、插件、配置文件及其他新接口默认不开放。
- 仅接受 `Authorization: Bearer …`，CPA 再验证真实密钥。短密钥、无密钥及错误密钥均不能调用。URL 查询参数不允许携带凭据。
- CPA 的 8317 及其他管理/回调端口只绑定 `127.0.0.1`，不直接开放给公网。
- API 响应设置 `no-store`，移除跨站读取许可，禁止索引；不向上游转发网站 Cookie 和其他认证头。
- 请求体上限 16 MB，最多 8 条到 CPA 的上游连接，支持流式响应及带 Bearer 鉴权的 Responses WebSocket。
- 不开启访问日志，不在公开调试输出中记录密钥。CPA 现有密钥和管理凭据继续保存在其私密配置中。

这些措施不等于绝对安全，也不是消费限额或完整抗 DDoS 服务。8 条连接不是每个用户的请求速率限制。若需要限制花费，应继续在上游账号设置预算或配额。

默认不支持任意第三方网页直接跨站调用；桌面/手机客户端一般不受浏览器 CORS 限制。需要网页客户端时，应单独审批可信域名，不要放开所有 Origin。

如果主站经过 Cloudflare，TLS 会在 Cloudflare 终止，它属于受信任的传输链路；并非只有客户端和本机才能看到请求。Mac、Docker 和 CPA 必须保持运行，Azure 游戏备用站不会自动获得 CPA 凭据。
