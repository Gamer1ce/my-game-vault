# 家庭公网 IPv6 网站：掉线诊断与预防

网站容器健康并不意味着公网可以访问。当前主站由家庭 Mac 托管，域名通过 Cloudflare 回源到 Mac 的公网 IPv6；视频直连同样依赖家庭 IPv6。两者不是互相独立的容灾线路。没有公网 IPv6 时，DDNS 无法凭空修复线路。

## 本次事件的证据（2026-09-27，北京时间）

- 02:45:44：macOS 日志显示自动分配的 IPv6 地址进入 detached/deprecated 状态。
- 02:49:27：地址有效期耗尽。Mac 随后连续发出三次 Router Solicitation；之后仍未恢复地址。
- 02:50：家庭网络 IPv4 DHCP 续租正常。这说明最初的故障不是误连加速盒，也不是整个 Wi-Fi 断开。
- 02:53：已有 DDNS 任务首次报告本轮“没有可用的公网 IPv6”。网站容器及本机 HTTPS 服务随后检查均正常。
- 故障期间的管理页面：锐捷 WAN 自身有 IPv6，但前缀为空、LAN IPv6 地址为空；光猫自身也有 WAN IPv6。
- 重启锐捷后，Mac 另行自动连接了无公网 IPv6 的加速盒网络。切回原家庭 5 GHz Wi-Fi 后获得 IPv6，更新 DNS 后公网主页返回 200，实际视频 Range 请求返回 206。

**可以确定：**原始故障在 IPv6 地址/前缀续租及内网广播链路，恢复时还叠加了 Wi-Fi 自动误连。

**不能确定：**缺少重启前光猫和锐捷的 DHCPv6-PD 报文/日志，不能据此断言某个固件版本有 bug，或断言运营商拒绝续租。macOS 的重复 DHCPv6 主机名隐私提示也不等于续租故障。

## 已有 DDNS 的保护措施

`scripts/cloudflare-ddns.mjs` 继续由本机既有 LaunchAgent 每 5 分钟执行，不需要开着终端。

- 使用 `ifconfig -L` 的地址状态和有效期，排除 deprecated、detached、tentative、duplicated、有效期为 0 的地址；不发布临时隐私地址。
- 检查对应接口的 IPv6 默认路由。可配置 `expectedGateway`，误连加速盒/热点时保留原 DNS，不把域名指向其他网络。
- 在已发布稳定地址仍可用时保持它，减少无意义的地址切换。
- Cloudflare 请求设置 10 秒超时；GET/PUT 遇到临时网络故障、429 或服务端故障时最多尝试 3 次。POST 创建记录不自动重试，以免重复创建。
- 每次记录网关、地址状态、剩余有效期；配置文件旁生成权限为 0600 的 `.status.json`，记录故障分类、连续失败次数、开始时间及上次成功地址。该文件不包含 API Token，不应提交到 GitHub。
- 这不是路由器自动修复器，也不代表已安装手机推送告警。不会自动重启设备、清空配置、修改 Wi-Fi 密码或放开防火墙。

配置示意（在原私密配置中追加，不要覆盖原令牌引用和域名设置）：

```json
{
  "interface": "en1",
  "expectedGateway": "192.168.110.1"
}
```

只读检查，不访问钥匙串、不修改 DNS：

```sh
node scripts/cloudflare-ddns.mjs --check
```

故障分类：`wrong_network` 为网关不符；`ipv6_missing` 为没有公网地址；`ipv6_unusable` 为地址存在但不可发布；`ipv6_route_missing` 为缺少对应接口默认路由；`dns_update_failed` 为 DNS API 更新失败。

## 日常预防

2026-09-28：站点所有者确认已手动关闭两个 UU 加速盒 Wi-Fi 的自动加入。随后复核 Mac 仍连接 `HW-5G`，家庭网关、稳定公网 IPv6 和默认路由正常，公网主页返回 HTTP 200。自动加入开关由用户操作并确认；本次复核未通过切断家庭网络来模拟故障。

1. 将家庭网络设为自动加入，关闭加速盒/热点的自动加入，保留手动连接能力。此项需要在 macOS Wi-Fi 设置中实际核实，不能只凭网络列表顺序推断。
2. 条件允许时让网站 Mac 用网线直连家庭路由器，减少 Wi-Fi 漫游和误连。但网线本身不能解决上游前缀续租失败。
3. 再发生时，先保存故障前后的地址有效期和路由器/光猫 DHCPv6-PD 日志，再决定重启；否则重启可能抹掉证据。
4. 不把关闭 IPv6 开关当作普通重启：本次锐捷页面明确提示该操作会删除全部 IPv6 配置。
5. 如果反复出现“WAN 有地址、PD 前缀为空、LAN 无地址”，向电信和锐捷提交时间线，要求检查光猫向下级路由器的前缀委派续租。不要凭猜测固定公网前缀或盲目更新固件。

真正消除家庭 IPv6 故障对主页的影响，需要独立的公网回源/备用承载方案，属于额外部署；本次未重新启用已退役的 Azure，也未启用新的隧道。
