# 原版 KEEPER 用量界面

首页的「AI 用量」按钮进入 `/ai-usage/`。原有 `/ai-usage.html` 地址自动跳转。直接复用本机 KEEPER 的 HTML、脚本、样式、图表和筛选，不另做一套仪表盘；游戏网站首页保持原有风格。

## 两种访问身份

- **访客**：使用 KEEPER 原生只读视图，查看总览、实时用量和分析。统计覆盖 KEEPER 已收集的全部客户端用量，而不是单个 API Key。服务端仅允许固定统计接口，并清除密钥维度、账号文件、上游地址和身份信息。
- **管理员**：点击上方「管理员登录」，使用游戏网站现有管理员密码；原版管理视图才可加载敏感信息。「连接信息」按钮可查看 CPA 客户端密钥和 Base URL。一分钟后或页面隐藏时清除该弹窗中的密钥。
- 公网入口仍是**只读**：即使管理员登录，也不允许修改价格、账号、密钥或配置；需要修改时在 Mac 本机使用原 KEEPER。

原版主题、语言、布局与时间筛选保留。网站额外提供一条小导航用于返回游戏档案和登录，没有把原版 UI 换成游戏网站风格。

## 部署

将网站容器与 KEEPER 加入同一个私有 Docker 网络。KEEPER 的 8320 端口继续只绑定 `127.0.0.1`，不要直接公开。当前连接本机 KEEPER 1.15.4，原本仅限本机访问、`AUTH_ENABLED=false`；桥接层使用游戏网站的管理员会话，不改变 KEEPER 本身设置。

```text
CPA_KEEPER_ORIGIN=http://cpa-usage-keeper:8080
CPA_USAGE_DB=/cpa-usage/app.db
CPA_PUBLIC_BASE_URL=https://你的域名/cpa/v1
```

将 KEEPER 的整个 data 目录**只读挂载**到 `/cpa-usage`，包括 SQLite WAL/SHM 文件，用于管理员按需读取已同步客户端密钥。参考 [Docker 配置](../deploy/cpa/compose.usage.example.yaml)，合并进现有部署，保留原来的数据卷和网络。

如果 KEEPER 自身已启用认证，应保留该认证，本桥接器会因上游拒绝而停止读取；不要为公开面板关闭一个原本受保护的上游服务。

## 安全边界

- 访客不是通过 CSS 隐藏密钥：未知接口、身份/日志/设置接口以及写操作在服务端被拒绝；公开 JSON 使用白名单清洗。
- 不转发浏览器 Cookie、Authorization 或自选上游地址到 KEEPER。固定目标、请求超时和响应大小上限限制代理范围。
- 管理员接口校验网站会话、同源和安全传输，所有代理响应禁止浏览器/CDN 缓存。
- 原始请求正文、错误日志、账号/凭据信息仅在已认证的管理员视图中可读；不要在共享设备上登录管理账号。
- 不上传 KEEPER 数据库、密钥或私有环境配置到 GitHub。原版资源运行时从本机 KEEPER 读取，本仓库不打包其第三方源码。
- 主站与备用站按钮统一进入主站面板，不把密钥库复制到 Azure；自行部署需更改首页按钮域名。
- 隐藏地址不是访问控制；CPA API 仍须独立校验访问密钥。统计不是账单，也不能补全 KEEPER 尚未收集的历史。
