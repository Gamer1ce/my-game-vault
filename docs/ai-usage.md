# 独立 AI 用量页面

首页的「AI 用量」按钮进入 `/ai-usage.html`，不在首页加载统计面板，也不把本机 8320 管理后台整体代理到公网。

## 访客与管理员

- 访客：累计/今日请求、成功率、输入/输出/缓存读取 Token、最近 30 天的每日汇总。
- 管理员：使用游戏网站已有的管理员账号登录，再点击「查看连接地址与密钥」，读取 CPA 客户端访问密钥及 Base URL。不是 KEEPER 的登录密码，也不是上游服务商密钥。
- 切换标签页、离开页面、退出登录或展示 60 秒后，页面清除已经展示的连接信息；不写入浏览器本地存储。
- 即使手动调用连接信息接口，未登录/伪造会话仍返回 401。服务器未开启管理员认证时也拒绝返回密钥。

## 接入现有 KEEPER

将 KEEPER **整个 data 目录以只读方式挂载**到网站容器的 `/cpa-usage`，包含 `app.db` 以及 SQLite 的 WAL/SHM 文件。不要复制数据库到 `public/` 或上传 GitHub。环境变量：

```text
CPA_USAGE_DB=/cpa-usage/app.db
CPA_PUBLIC_BASE_URL=https://你的域名/cpa/v1
```

当前适配 KEEPER 1.15.4 的日/小时汇总表和 `cpa_api_keys` 表。连接区的密钥来自 KEEPER 最近同步的有效客户端密钥，更新 CPA 密钥后应确认 KEEPER 已完成同步。

Docker 配置参考 [只读挂载示例](../deploy/cpa/compose.usage.example.yaml)，将内容合并到已有服务，保持原有数据卷和网络设置。

后端使用 SQLite 只读连接和数字字段白名单，不返回来源地址、IP、账号、请求正文、错误日志或原始事件。统计缓存 30 秒，页面可见时每分钟刷新；访客刷新页面不会消耗 AI 推理额度。

所有用量接口设置 `no-store`，管理员连接接口额外验证已有登录会话、同源和安全传输。不新增管理写接口，不修改 KEEPER 原始数据。8320 仍仅绑定本机回环地址。

## 限制

- 统计覆盖 KEEPER 已经收集的数据，不是账号的全部历史，也不是实际账单。
- 当前主站和备用站的入口统一跳转到主站用量页，避免向镜像服务器复制密钥或整个 KEEPER 数据库。自行部署时修改首页该按钮的域名。未配置用量库的实例直接访问本地用量页会显示服务不可用。
- 隐藏连接地址不是认证措施：地址可能被猜到。CPA 本身仍必须验证访问密钥，不能因页面隐藏地址而关闭验证。
- 已登录管理员的浏览器必须收到密钥才能显示；不要在共享设备展示或截图分享。
